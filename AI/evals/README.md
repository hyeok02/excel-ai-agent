# 검증 범위와 실행 방법

테스트 수가 많다는 사실만으로 모든 Excel 파일과 자연어 질문의 정확성을
보장하지 않는다. 결과는 아래 세 층으로 구분한다.

| 검증 층 | 확인하는 것 | 확인하지 않는 것 |
| --- | --- | --- |
| 공통 엔진 회귀 | 원본 값·단위·기간·대상, 전체 집계, 변경 범위 보존 | 실제 모델의 질문 해석 |
| 계획 주입 API | 모델이 제안할 수 있는 실행 계획을 API가 독립 검증·계산하는지 | 모델이 해당 계획을 실제로 선택하는지 |
| 실제 파일 오프라인 API | 원본 파일과 일반 질문을 모델 없이 처리한 결과 | 모델 생성이 필요한 요청의 최종 결과 |

`test_release_capabilities_api.py`는 두 번째 층이다. 실행 계획만 고정하고
답변 수치는 공급하지 않는다. 조인·합계·수식 계산·모호한 범위의 API 결과,
기대 숫자, 응답 상태, 검증 수준을 독립적으로 대조한다. 이는 실제 모델의
자연어 이해가 통과했다는 의미가 아니다.

## 유료 호출 없는 실제 파일 검사

AI 디렉터리에서 실행한다. 모델 생성과 네트워크 접근을 차단한 채 실제
FastAPI 경로를 메모리 안에서 호출한다. 원본은 읽기 전용이며 종료 시
SHA-256을 다시 대조한다. 매크로 실행이나 외부 데이터 갱신은 하지 않는다.

```bash
python -m evals.offline_acceptance \
  --cases evals/cases/capitaliq.json \
  --directory /path/to/workbooks \
  --output /path/to/reports/offline-acceptance.json
```

여러 폴더의 파일은 `--file-map`에 로컬 JSON을 지정한다:
`{"files":{"input.xlsx":{"path":"/absolute/path/input.xlsx"}}}`.
개인 파일과 절대 경로가 든 매핑·결과 보고서는 저장소에 커밋하지 않는다.
보고서는 원본 파일을 덮어쓸 수 없다.

판정은 답변 상태·필수/금지 문구·원본 셀 범위·검증 수준을 검사한다.
`verification_levels`로 허용 수준을 지정할 수 있다. `parent`가 있는 질문은
실제 앞선 응답의 근거를 이용하며, 원본이 다른 대화와 연결하지 않는다.
정답 숫자가 다른 회사의 셀에서 나왔거나, 정상 질문을 차단하거나,
모델이 필요해 실행하지 못한 경우는 통과가 아니다. 모호한 질문의 확인
요청은 처음부터 그렇게 정의한 테스트에서만 통과할 수 있다.

이전 시나리오가 현재 의도와 맞지 않아도 기대값을 실행 결과에 맞춰
자동 변경하지 않는다. 원본 셀·질문·단위·대상을 다시 확인하고 수정 이유를
리뷰한다. 보고서의 `model_required`는 무과금 검사 한계이며 실제 제품의
오답으로도, 정상 답변 검증 통과로도 계산하지 않는다.

## 변경 전후 필수 확인

공통 처리의 회귀 기준은 다음과 같다. 파일명이나 특정 회사·값으로 분기하지
않고 원본 표의 의미와 범위를 확인한다.

- 집계: 선택한 지표에 해당하는 통화·단위를 검사한다. 다른 금액 열의 통화로
  인원·수량 합계를 막지 않는다. 상세·소계·총계를 겹쳐 더하지 않으며,
  확인되지 않은 추가 조건을 버린 채 일부 행만 집계하지 않는다.
- 추이: 같은 대상·단위·기준 안에서 날짜순으로 계산한다. 중간 하락·반등과
  누락값을 보존하고, 서로 다른 회사의 값을 하나의 추세로 이어 붙이지 않는다.
  일부 시점만 화면에 표시하면 전체 기록인 것처럼 표현하지 않는다.
- 대상 확인: 법인 접미사가 생략된 원본 이름은 대조하되, 이름 일부나 값이
  같다는 이유로 서로 다른 표를 합치지 않는다. 후보에는 질문한 행의 값을 보여준다.
- 수정: 행·열 조건을 모두 만족한 대상만 허용한다. 새 문자열 속 `all`·`전체`를
  전체 행 수정 권한으로, `delete`·`삭제`를 셀 삭제 권한으로 사용하지 않는다.
  실제 적용 전 원본 값, 적용 후 비대상 XML·수식·서식·매크로 보존을 대조한다.

배열·행 순서·열 위치를 바꾼 대조군과 정상 요청 양성 사례를 함께 유지한다.
안전하지 않은 요청의 차단만 늘려서는 이 기준을 충족하지 않는다.

```bash
python -m pytest
```

CI에서 전체 테스트와 새 API 수용 테스트를 함께 실행한다. 새로 재현한
오답은 실패 테스트를 먼저 추가하고, 고친 뒤 정상 요청 대조군도 확인한다.
파일 이름·시트명·셀 위치를 바꾸거나 행 순서를 뒤집어도 같은 의미의
결과가 유지되는지 검사한다. 조건/단위/대상이 달라지는 변형은 다른 결과
또는 구체적인 확인 요청을 기대한다.

릴리스 판단 기준은 검증 범위 안에서 다음을 모두 만족하는 것이다:

- 잘못된 항목·숫자·기간·단위를 확인된 답으로 표시하지 않는다.
- 답할 수 있는 정상 요청을 무조건 차단해서 테스트를 통과시키지 않는다.
- 수정은 명시한 행·열 조건과 승인 값에 한정하며, 다른 값·수식·서식과
  원본 패키지의 비대상 부분을 보존한다.
- 누락 값, 상충하는 대상, 외부 수식 미계산을 0이나 임의 값으로 바꾸지 않는다.
- 테스트 실패·미실행·모델 필요를 성공률에서 숨기지 않는다.

새로운 파일 분포에 대한 정확도나 실제 모델까지 포함한 제품 준비 여부는
별도의 검증이다. `run_questions.py`, `run_conversations.py`,
`run_capabilities.py`는 실제 서버를 호출하므로 유료 모델이 실행될 수 있다.
유료 호출 금지 작업에서는 실행하지 않는다.
